# Android: Kotlin inventory (maximum-Rust migration, step 1)

Source: `android/src/main/java/MainActivity.kt` (1488 lines) and the JNI crate in `android/src/main/rust/`.

## Must stay in the Kotlin shell
- `MainActivity` lifecycle: `onCreate`, `onResume`, `onPause`, `onStop`, `onBackPressed`, `onActivityResult`.
- Permissions and system APIs: microphone recording/playback, camera QR scan, `BiometricPrompt`, Android Keystore (`HashChatKeystore`), `Settings.Global`, `Build.*` and `SystemProperties` reads.
- `System.loadLibrary` and the `external fun` declarations.

## Movable to Rust
| Kotlin today | Rust target | Status |
|---|---|---|
| `isStrictModeEnabled`, `shouldRefuseInStrictMode`, `reEvaluateSecurityPosture`, `isActionAllowedInPosture` (signal interpretation and gating) | `hashchat_rust::device_posture` | **Done:** JNI `evaluatePostureFromSignals` / `isActionAllowedForSignals`; Kotlin collects signals only |
| `loadPersistedGroups`, `persistGroups`, member add/remove, leave group (group list state) | `hashchat_rust::group_store::GroupBook` | **Done:** Rust owns the list (validation, limits, legacy `name:ids` migration); JNI `groupBook*`; Kotlin only renders and wraps `groupBookExport()` with the Keystore. Per-member sender keys persist via `groupSenderKeyBook*` (2026-10-15) |
| `performCrossDeviceExport` / import a carry file | `hashchat_rust::device_export` | **Done for one session move (2026-11-01):** Rust decides, wraps the sealed envelope as a carry file, and on the other device installs it. Extreme, strict posture, a weak or empty passphrase, the old hardcoded transfer passphrase, and a ratchet with a zero root are refused. One established session exports directly. Several sessions open a picker (`deviceExportEstablishedSlots`, labels `Session N`). Import (`deviceImportPrepare` / `deviceImportInspect` / `deviceImportInstall`) checks the carry file, then places the ratchet in the first empty slot under the 64-slot cap. It does not replace an established session and refuses a root that is already loaded. The shell only picks the file and types the passphrase. The exporting device keeps its copy. Still open: wiping that copy after a confirmed transfer, and a contact name on the picker line. Group envelope `ratchetExportEncrypted` is unchanged |
| `addMessage`, message list state, delivery state | `hashchat_rust::message_book::MessageBook` | **Done (2026-10-17):** Rust owns the transcript (stable ids, direction flag, delivery state, disappearing deadline, sanitised and capped text, 2000-entry bound, zeroize on removal); JNI `messageBook*`; Kotlin renders `messageBookTexts`/`messageBookMine` and Keystore-wraps `messageBookExport` into `messages.enc`; EXTREME/strict books are ephemeral (export nothing, file deleted). Bubble direction no longer comes from a `You:` text prefix |
| Decoy/extreme profile state (`onToggleDecoyProfile`, `EXTREME_MODE`) | `hashchat_rust::profile_slot` | **Done (2026-10-22):** Rust owns the Extreme flag and the primary/decoy screen (`profileConfigure`, `profileToggleDecoy`, `profileBlocks`). Memory only, not a second identity and not the desktop duress decoy. Strict posture blocks entry; leaving is always allowed. The shell parks the transcript (`messageBookPark`) so export keeps writing the primary chat |
| Voice chunk queue and framing | `hashchat_rust::voice_queue`, `hashchat_rust::voice_chain` | **Queue done (2026-10-24). Framing and the per-chunk chain done (2026-11-08).** The queue holds 32 chunks, each capped at one Tor frame, zeroized on take and on wipe, refused under Extreme. `voice_chain` pads every piece to 4096 bytes, seals it with AES-256-GCM under an HKDF message key, and advances the chain. Skipped keys cover a reordered recording. A bad frame does not move the chain. The seed is random and memory-only; wipe drops it. JNI `voiceSealRecording` / `voiceOpenBundle` / `processVoiceChunk`. The shell reads the microphone file and plays the opened bytes. It does not pass a key. Still open: carrying that seed inside a contact session, so a second device can open the recording. This is not a DH ratchet |
| Screens (RecyclerView adapters, dialogs) | Rust UI pilot (Slint or egui), step 3 | Open |

## Notes
- The JNI crate depends on `hashchat-rust` (path) and calls shared `device_posture` / will grow toward other shared modules.
- Kotlin keeps collecting raw signals only; Rust decides. Unknown action names are refused.
- Next: carry the voice seed inside an established contact session. The carry file is chosen on the other device and installed into an empty ratchet slot (`device_export`, 2026-11-01). Voice recordings are framed and sealed in Rust (`voice_chain`, 2026-11-08); the seed stays in the process. Group sender keys already persist via Keystore-wrapped `group_sender_keys.enc` (2026-10-15). The decoy screen is not the desktop duress decoy; that wipe-and-empty-profile path stays on the TUI.
